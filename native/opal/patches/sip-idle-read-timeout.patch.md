# Preserve an established SIP flow across idle reads

Apply after the 19 existing SDK patches, including `bfcp-session-open-state.patch`, against pinned OPAL `aeda428ced0b1d8c96d4290bea97362bceb7faf2`. This draft changes only `src/sip/sippdu.cxx`; the root build recipe owns application and rebuilt SDK provenance.

RED evidence: `evidence/devices/run11-final-controls/ex90-10.136.101.18-sip-aac-off.log`. INVITE CSeq 1–4 and their ACKs use the same original TCP flow to port 5060. The last received 200 is at 22.950 seconds (line 4592). At 102.972 seconds (line 7494), the SDK reports a read timeout and closes that flow. BYE at 103.141 seconds then attempts the peer's closed Contact port 42933 and ends in `Terminated_TransportError`, leaving the remote call visible. Local exit 0 did not prove remote termination.

The 80.022-second quiet interval matches the SDK read path: `OpalTransportTCP::OnConnectedSocket` initially uses transport idle 60 seconds plus 10 seconds; `SIP_PDU::Read` performs `peek()` with that timeout, then `Parse` clears the failed stream and retries under the 10-second signaling timeout. It mistakes an otherwise open, idle TCP flow for a lost transport. The established-flow guard correctly rejects that already-closed flow, so changing its IP/protocol checks would not fix this failure.

Retry only a pre-first-byte `peek()` EOF whose read error is exactly `PChannel::Timeout` while the transport remains open. Clear stream/read-error state and retry with the unchanged original read timeout. Once a byte arrives, existing signaling-timeout parsing still bounds partial or malformed PDUs. Genuine EOF/reset/close remains on the existing lost-transport path. An idle retry emits no SIP request or CRLF/PONG. Endpoint garbage collection still closes unreferenced idle transports, and explicit Close still interrupts the blocked read.

RFC 3261 section 18 permits an implementation-defined connection retention duration ([official RFC](https://www.rfc-editor.org/rfc/rfc3261.html#section-18)). Keeping a referenced active-dialog flow avoids relying on an unreachable ephemeral Contact. CRLF keep-alive introduces separate peer-support rules ([RFC 5626 sections 3.5.1 and 4.4.1](https://www.rfc-editor.org/rfc/rfc5626.html#section-4.4.1)); this patch does not enable that protocol.

`tests/SipDialogFlowTests.py --idle-seconds 90` keeps its owned localhost peer quiet after INFO 200, then requires BYE 200 on the same accepted TCP flow with an intentionally closed Contact. The fixture records the requested wait, actual quiet gap before BYE, accepted socket endpoints, monotonic request/response times, and clean worker exit. `--idle-seconds` accepts 0..120, defaults to 0, and the peer read timeout exceeds the requested wait by 30 seconds. Normal CTest remains short. The final SDK owner must run the 90-second fixture and verify real EOF/partial-PDU behavior before claiming GREEN.

`tests/SipReadFailureTests.py --worker <path> --logs <directory>` establishes valid owned TCP dialogs and checks two separate failures. `--case eof` half-closes the peer's write side, requires SDK TCP/read-thread closure within 5 seconds, and then a clean worker exit. `--case partial` sends only the first byte `S`, requires closure in 8..16 seconds under the unchanged approximately 10-second signaling timeout, and then a clean worker exit. Its default `--case all` runs both sequentially; default worker ports are SIP 15250, H.323 17975 and RTP 49000. All peer signaling and RTP/RTCP destinations are owned localhost sockets. This separate fixture leaves the positive idle test unchanged.
